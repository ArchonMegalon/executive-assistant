## Objective

Implement the accepted generic execution foundation that lets the shared EA
media-factory recover an exact approved scene, route, style, and asset set after
restart without trusting a provider or caller-controlled path.

The same foundation must support:

- PropertyQuarry continuous one-scene walkthroughs with no encounter overlay;
- Chummer continuous Runsite walkthroughs with no encounter overlay; and
- Chummer private fictional non-graphic encounter previews with the accepted
  encounter overlay contract.

Do not hardcode a Property style, IKEA, botanical direction, MagicFit, OMagic,
Blender, 3DVista, Pano2VR, Crezlo, or combat scene into the shared foundation.
Styles and provider routes enter only through accepted immutable registries,
content-addressed bindings, and exact family/profile dispatch.

This milestone does not execute a provider or produce a render.

## Contract implementation

Implement the exact accepted R11 types and strict unknown-member rejection.

1. Add optional `source_packet_created_at` to source packet v1 for backward
   parsing. R11 compose requires an offset-aware value satisfying
   `source_retrieved_at <= source_packet_created_at <= compose_observed_at`.
   R9/R10 may omit it and cannot acquire one in place.
2. Implement exact typed models for execution material, render specification,
   style snapshot, asset binding, encrypted envelope, execution request,
   execution result, operation reconciliation, normal Property projection, and
   Property deletion projection. Use the identifiers, member allowlists,
   bounds, enums, and cross-field rules in accepted R11 and Property authority.
3. Preserve the exact Revision 10 ordered route and actual revisit flag. The
   render specification must recover the same route, full walkable set,
   portals, camera, output, overlays, and digests; no provider/style branch may
   alter geometry or route.
4. Implement exact product/family/profile resolution:
   - PropertyQuarry continuous walkthrough ->
     `propertyquarry_continuous_walkthrough` plus
     `spatial_orientation_no_encounter_fields`;
   - Chummer continuous Runsite walkthrough ->
     `runsite_continuous_walkthrough` plus
     `spatial_orientation_no_encounter_fields`;
   - Chummer private fictional encounter preview ->
     `runsite_private_encounter_preview` plus
     `private_fictional_non_graphic_encounter`.
5. Reject every other product/family/profile/purpose/overlay combination before
   compose acceptance. Property overlays are empty. Do not weaken the existing
   fictional, non-graphic, no-real-person, no-minor encounter rules.
6. Dispatch the exact v1/v2 evidence identifier pair before validation. Keep v1
   immutable. Reject mixed identifiers, unknown versions, Property under v1,
   Property under either Runsite family, or a Runsite family carrying the
   Property policy object/evidence/gate.
7. Extend semantic verification for the exact Property owner, family, profile,
   numeric-policy object/evidence ref, matching digest, chronology, 24-hour
   freshness, expiry ordering, gate version, and top-level expiry.
8. Do not depend at runtime on a mutable cross-repository pathname. Expose a
   controller-injected, digest-bound schema-validator/descriptor boundary.
   Tests may construct it from the pinned v1/v2 authority files after verifying
   their hashes and modes.

## Encrypted execution material

Implement `governed_spatial_execution.py` as the generic private execution
boundary.

- Use exactly AES-256-GCM, 32-byte keys, fresh 12-byte nonces, and 16-byte tags.
- Implement the exact environment/key-ref/epoch/fingerprint registry and
  `active_encrypt_decrypt`, `decrypt_only`, and `revoked` states.
- Build bounded no-float JCS plaintext and AAD exactly as accepted. Keep
  `material_digest` outside plaintext. Authenticate every envelope member
  except ciphertext and `aad_digest` and verify before decrypting/trusting.
- Store no plaintext material or plaintext temporary file. Redact secrets,
  material refs, rooms, source refs, nonces, ciphertext, paths, and key bytes
  from errors, projections, telemetry, and receipts.
- Use a private controller root `0700`, regular records `0600`, `lstat`,
  no-follow opens, owner/mode checks, descriptor identity checks, atomic
  same-directory writes, fsync ordering, and traversal/symlink/race rejection.
- Implement the append-only hash-chained material journal with monotonic
  sequence and exact seal/delete states. Recover a valid ciphertext after
  `seal_intent`; otherwise remove invalid bytes and append
  `seal_aborted_missing_ciphertext`. Exact replay repair is allowed only under
  accepted R11 rules and never across a tombstone.
- Persist tombstone before ciphertext unlink. Tombstone wins over replay,
  reconciliation, rotation, and restore. Return only the accepted typed
  deletion projection.
- Fix retention to
  `min(source_packet_created_at, compose_acceptance_at) + policy source days`,
  capped by policy expiry and every shorter rights/consent/takedown/privacy
  deadline. No build/replay/retry/rotation/attempt clock reset.
- Keep encryption keys dependency-injected. Do not read or create production
  credentials, keys, environment files, or account state.

## Orchestrator integration

1. Compose R11 only after independently verifying current product policy,
   source authority, style snapshot, asset bindings, and exact family/profile.
   Recompute all normalized digests and create the complete material plaintext.
2. Write the accepted signed composition receipt, then seal material. Compose
   reports accepted only after `sealed`. A crash before seal leaves a
   non-executable receipt and follows the exact repair rules.
3. Inject product-policy verification into the runtime. Do not add caller-owned
   policy fields to the Property input contract. For PropertyQuarry, verify the
   exact accepted policy path/hash/mode and independent evidence before compose,
   immediately before `seal_intent`, and before build.
4. Build must cryptographically verify the complete stored composition
   envelope with a controller-injected environment-scoped Ed25519 registry
   before reading material or considering quota.
5. Decrypt and type-validate material, recompute every digest, rerun cross-
   source route validation, resolve exact style/assets, and compare all lineage
   to the signed composition before any output allocation, quota, adapter,
   provider, or verifier action.
6. Add the optional compose transport member
   `supersedes_composition_digest` only for explicit R9/R10 -> R11 recompose.
   Ordinary compose rejects it. Old receipts remain byte-for-byte audit replay;
   build returns zero-action `r11_recompose_required`. Permanently disqualified
   artifacts cannot seed recompose.
7. Preserve current R9/R10 behavior and every accepted Revision 9/10 invariant.

## Adapter, resolver, verifier, and reconciliation interfaces

Implement strict interfaces and local fakes only. Do not implement or invoke a
live provider route.

- Asset resolver: opaque execution-safe refs only, allowlisted private roots,
  no-follow regular-file opens, exact owner/mode/hash/size checks on the open
  descriptor, and pinned descriptor or immutable controller staging. Never
  verify then reopen a pathname.
- Output allocator: controller-owned already-open private capability only. No
  caller/provider output path.
- Adapter request/result: exact accepted contracts. Reject unknown members,
  paths, URLs, executable/command/shell syntax, dynamic import, provider ids,
  secrets, raw traces, and adapter-supplied quality metrics.
- Route resolver: controller-injected exact allowlist with digest equality. No
  environment-selected fallback or arbitrary endpoint/executable.
- Artifact verifier: a separate injected interface whose input binds output,
  manifest, source geometry, scene, controller camera timeline, toolchain,
  style/assets, route, and provenance. This milestone defines and validates the
  interface/receipt only; it does not render or claim quality.
- Reconciliation: exact signed contract, operation/state enums, adapter
  binding, five-minute freshness, prior digest, strictly increasing sequence,
  monotonic transitions, terminal restatement, and stale `not_started`
  rejection. Implement durable validation hooks and local fakes without any
  provider/quota action.
